# مواصفات الصفحات — Page Specs
## كل شاشة: الغرض · البنية · الحالات · التنقل

> **الغرض:** المرجع الحرفي لبناء ومراجعة كل صفحة. البنية الموصوفة هنا هي العقد — أي انحراف عنها في الكود هو عيب يُصلح أو قرار يُوثّق هنا أولًا.
> **الاصطلاح:** الأقسام مرقمة من أعلى الصفحة إلى أسفلها. «الحالات» تعني تقلبات الشاشة. المصطلحات التقنية بلغة CSS/TSX موجودة لتوجيه المطور مباشرة.

## B. التطبيق — الغلاف المشترك

### B-0 · App Shell (كل مسارات `/app/*`)

**الغرض:** الإطار الموحّد: شريط علوي (علامة + بحث/أمر + لغة + ثيم + تنبيهات + دخول إعدادات) وقائمة جانبية ثلاثية المجموعات.

- **الأوضاع:** هاتف = drawer + شريط سفلي بخمس وجهات · تابلت = rail قابل للتوسيع · سطح مكتب = موسّع قابل للطي (يُحفظ في localStorage).

- **لوحة الأوامر:** ⌘K تبحث في الـ15 وجهة (React state + تصفية label).

## D. المساحات النطاقية (learn · research · create · code · analyze · explore)

مساحات منجزة بمركّب `domain_workspace` عبر سجل الخدمة. لكل منها بنية متخصصة (مسارات فصول/خطط بحث/موجزات إنشاء) تشترك في آلة الحالات الجوهرية ذاتها. البنى الثلاث الأولى (تعلّم/ابحث/أنشئ) موثقة أدناه بدقة كما هي في الكود — قاعدة W-3: لا تعديل قبل توثيق. خدمات برمج/حلّل/استكشف تُقلب إلى النمط ذاته عبر السجل؛ توثق كل شريحة في مواصفتها (D-4/D-5/D-6) لحظة هبوطها لا قبلها.

### D-0 · النمط المشترك للمساحة النطاقية (كل ما يسبق الأسطح)

مصدر البناء: `src/features/{service}/{service}-workspace.tsx` فوق `ServiceWorkbenchProvider` + `ServiceWorkbenchShell`.

| # | القسم | المحتوى | ملاحظات بناء |
|---|---|---|---|

| 2 | شارات | «محاكاة معلنة» (تفتح الإيصال) + «التخزين التجريبي» (تفتح الإفصاح) | من قاموس workbench |

| 4 | أدوات التشغيل | ابدأ المحاكاة / إلغاء / إعادة / أكمل المدخل + حالة التشغيل + احفظ تجريبيًا / امسح البيانات | المحاكي الحتمي من mock-api |

### D-1 · تعلّم `/app/learn` (U2-LRN-001) — 8 مراحل

**الهوية:** تشخيص قصير → مسار قابل للتعديل → درس وتحقق وتغذية راجعة.

| # | المرحلة (الحالة) | المحتوى والسلوك |
|---|---|---|
| 1 | `lrn_brief` الهدف والوقت | تبديل موجّه/سريع + منتقى موضوع (3 مواضيع بملخص) + دافع (نص) + شرائح دقائق 5/15/30 + شرائح مستوى مبتدئ/متوسط/متقدم. سريع يقفز التشخيص إلى مراجعة المسار بمسار ذاتي التقييم |
| 2 | `lrn_diagnostic` التشخيص | سؤال-بسؤال يدويًا (لا تقدم تلقائي)، أوزان الاختيارات محلية موثقة، «لا أعرف» خيار محترم، التخطي يُسجل ويسبب مسارًا تأسيسيًا أولًا |
| 3 | `lrn_path_review` ⭐ مراجعة المسار | وحدات المسار بترتيب قابل للتحريك أعلى/أسفل + تخطٍ بسبب موثق + استعادة + مسوَّغات الترتيب (details) + تأكيد |
| 4 | `lrn_lesson` الدرس | مقاطع الدرس + مثال + مطالبة تفاعل (يجب تفاعل حقيقي قبل التحقق — لا يكفي التمرير) |
| 5 | `lrn_check` التحقق | اختيار متعدد أو نص حر + سلّم تلميح من مستويين (لا يعطي الجواب) + إرسال/تخطي |
| 6 | `lrn_feedback` التغذية الراجعة | شارة نتيجة (صحيح/جزئي/خطأ/تخطي) + تفسير + مثال مضاد + خطوة تالية + إعادة أو اعتماد |
| 7 | `lrn_checkpoint` ⭐ نقطة تقدّم | عدّاد التقدم (مكتمل/إجمالي — لا نسبة إن كان الإجمالي 0) + حفظ تجريبي + معاينة نقل إلى ابحث |
| 8 | `lrn_complete` نهاية الوحدة | اكتمال المسار + حفظ + نقل |

**الحالات الحدية:** موضوع غير مدعوم = حالة فارغة من الدرجة الأولى (موجز بلا مسار + عرض المواضيع البدائية) · `dense` يصل 12 وحدة (سقف العقد) · rtl_mixed يستخدم موضوع الطباعة العربية.

### D-2 · ابحث `/app/research` (U2-RSH-001) — 8 مراحل

|---|---|---|
