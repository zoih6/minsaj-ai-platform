# خارطة الطريق — Roadmap
## أولويات المراحل القادمة بترتيب منطقي

> **الغرض:** ترتيب العمل القادم بحيث يُبنى كل شيء على أساس مستقر. القاعدة: **منطق قبل جمال، هيكلة قبل ميزات.**

---

## المرحلة W-1 · ربط منطق الاختيار (الأولوية الأولى)

> «حين يختار المستخدم نمط العمل وأسلوب التنفيذ، تُهيكل الصفحة بدقة — لا زينة.»

| المهمة | المرجع | قبول |
|---|---|---|
| تنفيذ مصفوفة أداة العمل (التلميح/المخرج/البدايات/الإتاحات) | interaction-logic §2 | I-1 كامل الأثر |
| تنفيذ سلوك موجّه/سريع (أسئلة توضيحية مقابل تنفيذ مباشر) | interaction-logic §3 | I-2 كامل الأثر |
| ربط حبتي الإتاحة (ملف/صوت) بسلوك حقيقي (منتقي/حالة) | interaction-logic §5 I-9 | إتاحة قابلة للملاحظة |
| نقل تعريف أدوات الخدمات إلى `universal-content.ts` (بيانات لا كود) | architecture §3 A-5 | المكوّن يستهلك البيانات |

**بوابة الخروج:** FR-3.1–3.3 تتحول إلى «منجز» + مراجعة بصرية تمر + بناء نظيف.

## المرحلة W-3 · إكمال المساحات النطاقية

- توثيق بنى تعلّم/ابحث/أنشئ الحالية في page-specs (القاعدة: لا تعديل قبل توثيق).
- قلب خدمات `code/analyze/explore` من النموذجية إلى نطاقية عبر السجل (شريحة لكل خدمة، بنمط learn/research/create).
- كل قلب يتطلب: مواصفة صفحة + سطح تحقق في `/preview` + receipt بأدلة (نمط السجل الحالي).

## المرحلة W-4 · الحفظ والاستئناف الحقيقيان

- ربط الحفظ بطبقة خلفية عبر العقود القائمة (data-model §5).
- FR-4.3: فتح عنصر مكتبة يستأنف تكوينه (خدمة/أداة/أسلوب/ملقّن).
- مسودات تلقائية عند المغادرة (F-1 خطوة 6).

## المرحلة W-5 · الحسابات والمصادقة

خارج نطاق الأساس الحالي — تُفتح بقرار من المالك: هويات، أدوار حقيقية لصفحة الفريق، وربط الفوترة بمزود حقيقي.

---

## قواعد الخارطة

1. لا تبدأ مرحلة قبل اكتمال بوابة خروج سابقتها.
2. كل مهمة تُنفّذ بمقياسها المرجعي المذكور — لا «تحسينات جانبية» غير موثقة.
3. إضافة مهمة جديدة = إدراجها هنا بمرجعها قبل التنفيذ.
4. إنجاز مرحلة يُعلن في CHANGELOG بمعرّفات المتطلبات المحققة.
