# PRD — وثيقة متطلبات المنتج
## منسج · Minsaj — منصة عمل موحّدة للذكاء الاصطناعي، عربية أولًا

> **حالة الوثيقة:** مرجعية حيّة (Living Document) — تُحدَّث مع كل قرار منتج جوهري.
> **النسخة:** 1.0 · **تاريخ آخر تحديث:** 2026-09-21
> **المالك:** مالك المنتج (المستخدم) + وكيل التطوير.

## 1. ملخص المنتج

**منسج** منصة عمل موحّدة للذكاء الاصطناعي، عربية أولًا، تساعد المستخدم على الانتقال من النية أو السؤال إلى نتيجة منظمة يمكن فهمها وتعديلها وحفظها والعودة إليها لاحقًا. الاستعارة المؤسِّسة للعلامة هي **النسيج**: أفكار المستخدم خيوط، والمنصة النول الذي يحوّلها إلى قطعة مكتملة — «أفكارك خيوط ونحن ننسجها واقعًا».

بدل أن يبدأ المستخدم باختيار نموذج أو أداة، يبدأ من المهمة التي يريد إنجازها، ثم يوجّهه المنتج إلى مساحة العمل المناسبة ضمن تجربة واحدة متماسكة:

```text
النية → مساحة العمل → السياق → التنفيذ → مخرج منظم → الحفظ → الاستئناف والتطوير
```

هذا الخط هو **قانون المنتج الأول**: كل شاشة وكل تفاعل في المنصة يجب أن يخدم خطًا واحدًا على الأقل من هذا التسلسل، وأي عنصر لا يخدمه هو زينة يجب إزالتها.

## 2. المشكلة التي يعالجها المنتج

يعتمد المستخدم العربي حاليًا على أدوات ومحادثات منفصلة لإنجاز مهمة واحدة. النتيجة المعتادة: فقدان السياق بين الأدوات، تكرار شرح المطلوب في كل مرة، صعوبة اختيار الأداة المناسبة من بين عشرات الخيارات، نتائج غير منظمة تضيع في سجل محادثات لا يمكن الرجوع إليه بشكل عملي.

تتفاقم المشكلة في السوق العربي تحديدًا لأسباب ثلاثة. أولًا: ضعف دعم اللغة العربية واتجاه RTL في المنتجات العامة، فتظهر النصوص مقلوبة الأسطر أو مضغوطة الرأس. ثانيًا: واجهات توحي أحيانًا بأن بحثًا أو تنفيذًا قد حدث بينما لم يحدث فعليًا (ثقة زائفة)، وهو ما يجعل المستخدم الحذر يعيد العمل يدويًا. ثالثًا: أدوات الذكاء الاصطناعي المتاحة تُسأل المستخدم «أي نموذج تريد؟» بدل «ماذا تريد أن تنجز؟»، فتنقل عبء الاختيار التقني إلى غير التقني.

منسج يعالج المشكلة من جذرها: **مهمة واحدة، مساحة واحدة، نتيجة واحدة قابلة للحفظ والاستئناف** — بلغة عربية أصلية وتصميم RTL حقيقي.

## 3. الحل

يوحّد منسج الخدمات الأساسية في مساحة عمل واحدة، مقسّمة إلى مسارات واضحة:

| الخدمة | المعرّف | الغرض |
|---|---|---|
| **اسأل / Ask** | `ask` | محادثة مباشرة مع المساعد — البوابة المشتركة لكل نية غير محددة. |
| **تعلّم / Learn** | `learn` | مسارات تعلّم ومحتوى تعليمي منظّم قابل للاستئناف. |
| **ابحث / Research** | `research` | البحث والتحليل وتجميع النتائج في خطة قابلة للتوجيه. |
| **أنشئ / Create** | `create` | إنشاء المستندات والعروض والمحتوى المرئي. |
| **برمج / Code** | `code` | مساحة مخصّصة لمهام البرمجة والمراجعة. |
| **حلّل / Analyze** | `analyze` | تحليل المعلومات والبيانات إلى مخرجات قابلة للتتبّع. |
| **استكشف / Explore** | `explore` | استكشاف موضوعات وأفكار جديدة برحلات شخصية. |
| **مكتبتي / Library** | `library` | حفظ النتائج والعودة إلى الأعمال السابقة. |

وتدعم المنصة طبقة أدوات متقدمة لإدارة المشاريع والوكلاء والتدفقات ومصادر المعرفة والنماذج، وطبقة تشغيل للفوترة والاستخدام والفريق وسجل التشغيلات.

## 4. وعد المنتج

> **من فكرة بسيطة إلى نتيجة يمكنك فهمها وتعديلها وحفظها والعودة إليها.**

مؤشرات نجاح الوعد (عند ربط الطبقة الحقيقية):

| المؤشر | التعريف | الهدف |
|---|---|---|
| إكمال المهمة | نسبة الجلسات التي تنتج مخرجًا محفوظًا في المكتبة | > 40% |
| العودة خلال أسبوع | نسبة المستخدمين الذين يفتحون عنصرًا محفوظًا خلال 7 أيام | > 25% |
| زمن أول مخرج | الوقت من فتح الخدمة حتى أول نتيجة منظمة | < 3 دقائق |
| ثقة العرض | صفر حالات واجهة توحي بتنفيذ لم يحدث | 100% |

## 5. المستخدمون المستهدفون

| الشخصية | الاحتياج الأساسي | الخدمة المدخلة |
|---|---|---|
| **المحترف المستقل** (باحث/مستشار) | بحث وتلخيص وإعداد مخرجات جاهزة للتسليم | research · analyze · create |
| **صانع المحتوى** | تحويل الفكرة إلى موجز ومحتوى منظّم قابل للتطوير | create · ask |
| **المطوّر** | فهم الكود وتخطيط التغييرات ومراجعتها بأمان | code |
| **المتعلّم** | مسار تعليمي واضح يمكن استئنافه من حيث توقف | learn · explore |
| **قائد الفريق الصغير** | تنظيم المشاريع والأدوار وسجل العمل والتكلفة | projects · agents · usage |

الشخصية الجامعة بينهم: **مستخدم عربي غير تقني أو شبه تقني، يريد نتيجة لا أداة**، ويقدّر الوضوح والتنظيم على المرونة التقنية الخام. لهذا يخفي منسج أسماء النماذج خلف نوايا العمل، ويظهر التقنية فقط عندما يطلبها المستخدم المتقدم.

## 6. نطاق النسخة الحالية

النسخة الحالية هي **أساس واجهة وتجربة المنتج** (UI/UX Foundation) على طبقة بيانات تجريبية كاملة الأنواع (typed mock). تحتوي:

- واجهة عربية أولًا مع دعم كامل للعربية والإنجليزية واتجاهي RTL/LTR عبر مسار `[locale]`.
- غلاف تطبيق موحّد (App Shell) بقائمة جانبية ثلاثية المجموعات + لوحة أوامر ⌘K + تنبيهات.
- صفحات التسويق، التطبيق، المعاينة، الإدارة، ومساحات العمل.
- مساحات نطاقية منجزة لـ Learn وResearch وCreate، وبوابة خدمات نموذجية (Service Gateway) لـ Ask وCode وAnalyze وExplore.
- واجهات المشاريع والوكلاء والتدفقات والتشغيلات ومصادر المعرفة والنماذج.
- طبقة بيانات `packages/mock-api` بعقود مخطّطة بـ Zod بدل الخدمات الخلفية الحقيقية.

### خارج نطاق النسخة الحالية (صريحًا)

- أي استدعاء حقيقي لنماذج ذكاء اصطناعي أو خدمات خارجية — كل «التنفيذ» محاكاة أمامية.
- مصادقة مستخدمين حقيقية أو تعدد حسابات فعلي.
- مدفوعات حقيقية — صفحتا الفوترة والتعبئة محاكاة صريحة لا تجمع بيانات بطاقة.
- مزامنة سحابية — حالة «الحفظ» محلية داخل الجلسة فقط.

## 7. مبادئ المنتج غير القابلة للتفاوض

1. **العربية أولًا.** التصميم يبدأ RTL ويُعكس إلى LTR، لا العكس. القياسات الطباعية تُضبط للعربية أولًا (ارتفاع سطر 1.7 للنصوص، تتبّع صفري للعناوين).
2. **النية قبل الأداة.** المستخدم يختار ماذا يريد، لا أي نموذج يشغّله. أسماء النماذج تظهر فقط في مساحات المتقدمين.
3. **لا ثقة زائفة.** لا يجوز أن توحي أي واجهة بتنفيذ لم يحدث. كل محاكاة معلَنة بوضوح («بيانات تجريبية»، «محاكاة»).
4. **كل شيء قابل للحفظ والاستئناف.** أي مخرج يظهر في شاشة يجب أن يكون له مسار موثّق إلى المكتبة.
5. **المنطق قبل الزينة.** أي تفاعل مرئي (زر، بطاقة، تبديل) يجب أن يُغيّر شيئًا حقيقيًا في المسار أو البنية. الزينة بلا منطق عيب تصميمي يُرفض عند المراجعة.

## 9. قيود المنتج

- **عقد الإطار:** Next.js 16 مع App Router — لا صفحات من نمط Pages Router.
- **البيانات:** خلال مرحلة الأساس، مصدر الحقيقة هو `packages/mock-api` — لا يُضاف أي عميل API حقيقي قبل قرار المالك.
- **المستودع عام.** يُمنع منعًا باتًا وضع أي توكن أو مفتاح أو بيانات سرية في أي ملف داخل المستودع.
- **النشر:** Vercel بنشر تلقائي من فرع `main` — كل دفعة إلى main تظهر مباشرة في الإنتاج.
